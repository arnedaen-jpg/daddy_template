# 备用域名方案设计文档

## 背景

当前 `_fetchRemoteConfig` 直接使用 `EnvConfig.apiBaseUrl` 请求配置接口。如果域名被封禁，用户将无法获取 AB 配置，永远停留在 primary 模式。

需要引入多级备用域名机制，确保在各种封禁场景下仍能获取配置。

---

## 封禁场景分析

| 封禁类型 | 场景 | 影响 | 应对 |
|----------|------|------|------|
| 域名封禁 | 域名被 DNS 污染或运营商拦截 | 同一域名全国不可用 | 备用域名（不同域名） |
| IP 封禁 | 服务器 IP 被某地区/运营商屏蔽 | 特定地区用户无法访问 | 备用域名解析到不同 IP/不同机房 |
| CDN 账号封禁 | 服务商检测违规，封禁账号 | 该 CDN 上的配置文件不可用 | 多 CDN 源兜底 |
| CDN 流量异常 | 突发流量触发风控 | 临时封禁 | 多 CDN 源兜底 |
| 服务商故障 | 单一服务商出现故障 | 该源不可用 | 多 CDN 源兜底 |

### IP 封禁的应对

备用域名列表中的域名应满足：
- 解析到**不同 IP 段**（不同云服务商/不同机房）
- 分布在**不同地理区域**（境内多地区 + 境外）
- 使用**不同云服务商**的服务器（阿里云、腾讯云、AWS 等）

这样即使某个 IP 段被特定地区封禁，其他域名指向的不同 IP 仍可正常访问。

## 核心流程

```
_fetchRemoteConfig()
│
├─ 1. 用缓存的「上次成功域名」请求 config API
│     ✓ 成功 → 解析配置，结束
│     ✗ 失败 ↓
│
├─ 2. 用 EnvConfig 默认域名请求（跳过已试过的）
│     ✓ 成功 → 保存域名，解析配置，结束
│     ✗ 失败 ↓
│
├─ 3. 加载域名列表（优先级：缓存 → CDN → 硬编码兜底）
│     3a. SharedPreferences 缓存（未过期） → 使用缓存
│     3b. 依次从多个 CDN 源下载加密域名列表
│         按优先级尝试：阿里云 OSS → 七牛云 → Cloudflare R2 → ...
│         ✓ 任一成功 → 解密，缓存，得到域名列表
│     3c. CDN 全部失败 → 使用硬编码的兜底域名（字节数组存储在代码中）
│     ✗ 无任何域名可用 → 放弃，保持默认配置（primary mode）
│
├─ 4. 遍历域名列表，逐个尝试请求 config API
│     ✓ 某个成功 → 保存域名，解析配置，结束
│     ✗ 全部失败 → 放弃，保持默认配置（primary mode）
│
└─ 结束
```

> **注意**：兜底域名以字节数组形式硬编码在 `lib/utils/s.dart` 中，不使用 asset 文件，
> 避免 IPA 中出现可被静态扫描识别的文件名特征。
> CDN 加密文件由 `scripts/encrypt_domains.sh` 生成后手动上传。

## 多 CDN 兜底策略

### CDN 源列表（按优先级）

| 优先级 | 服务商 | 说明 |
|--------|--------|------|
| 1 | 阿里云 OSS | 国内覆盖最广，首选 |
| 2 | 七牛云 | 国内备选，用户群体大 |
| 3 | Cloudflare R2 | 海外节点，不受国内服务商管控 |
| 4 | 可扩展 | 后续可添加更多源 |

### 运维建议

- 每个 CDN 使用**独立账号**，避免连坐封禁
- 每个 CDN 上的文件**路径和文件名不同**，降低关联性
- 定期轮换 CDN 账号和路径
- 所有 CDN 源的 URL 在代码中以**字节码数组**存储
- 更新域名列表时，所有 CDN 源**同步更新**

## CDN 域名列表：零宽字符隐写

### 方案说明

CDN 上托管一篇**完全正常的文章**（健康/旅游/美食等），域名数据以不可见的零宽 Unicode 字符嵌入文章中。

优势：
- CDN 内容是普通文章，不会被 CDN 服务商标记或封禁
- 肉眼、浏览器、编辑器中完全看不到隐藏数据
- 无加密/Base64，不存在可疑的二进制内容

### 编码规则

| Unicode 字符 | 编码 | 名称 | 可见性 |
|-------------|------|------|--------|
| U+200B | bit `0` | 零宽空格 | 不可见 |
| U+200C | bit `1` | 零宽非连接符 | 不可见 |

多个域名用 `\n` 分隔，整体 UTF-8 编码后逐位转为零宽字符。

### CDN 上实际内容（看起来完全正常）

```
如何保持健康的生活方式

在现代社会中，越来越多的人开始关注自己的身体健康...
（零宽字符隐藏在此段落末尾，肉眼不可见）

均衡饮食是健康的基础。营养学家建议...
```

### 编码工具

```bash
# 生成文章模板
python3 scripts/encode_article.py gen-article --output config/article_template.txt

# 将域名编码嵌入文章
python3 scripts/encode_article.py encode \
    --domains config/domain_fallback.json \
    --article config/article_template.txt \
    --output config/output/healthy-life.txt

# 验证解码
python3 scripts/encode_article.py decode --input config/output/healthy-life.txt
```

### CDN 源列表

| 优先级 | 服务商 | 说明 |
|--------|--------|------|
| 1 | 阿里云 OSS | 国内覆盖广，首选 |
| 2 | Gitee | 国内代码托管，作为备用源 |

### 运维流程

1. 编辑 `config/domain_fallback.json` 更新域名
2. 准备文章模板（或用 `gen-article` 生成）
3. 运行 `encode` 命令生成含隐写数据的文章
4. 分别上传到阿里云 OSS 和 Gitee 仓库
5. 所有 CDN 源的 URL 以**字节码数组**存储在 `lib/utils/s.dart`

## 开发者选项：Fallback 模拟测试

在现有的开发者调试面板中新增以下功能，仅 `kDebugMode` 下可用：

### 功能列表

| 功能 | 说明 |
|------|------|
| 域名状态查看 | 显示当前工作域名、缓存域名、默认域名 |
| 强制触发 fallback | 模拟默认域名不可用，强制走 CDN → 域名探测流程 |
| 模拟全部失败 | 模拟所有域名不可用，验证最终降级到 primary mode 的行为 |
| 清除缓存域名 | 清除 SharedPreferences 中的工作域名缓存 |
| 手动指定域名 | 手动输入域名进行测试 |
| Fallback 日志 | 实时展示 fallback 流程的每一步结果（域名、耗时、成功/失败） |

### 模拟机制

`DomainManager` 提供调试开关：

| 开关 | 效果 |
|------|------|
| `debugForceFailDefault` | 默认域名和缓存域名请求直接返回失败，强制进入 CDN fallback |
| `debugForceFailAll` | 所有域名请求都返回失败，测试全部失败的降级行为 |
| `debugOverrideDomain` | 指定域名覆盖，跳过所有探测逻辑直接使用该域名 |

这些开关的状态通过 SharedPreferences 持久化，app 重启后保持。

## 新增组件：DomainManager

单例服务，职责：

| 职责 | 说明 |
|------|------|
| 缓存管理 | SharedPreferences 持久化上次成功的 API 域名 |
| 多源 CDN 获取 | 依次尝试多个 CDN 源下载加密域名列表 |
| 解密域名列表 | AES-256-CBC 解密 CDN 文件内容 |
| 域名探测 | 逐个尝试域名请求 config API |
| 调试支持 | 提供模拟开关和状态查看 |
| 对外接口 | `fetchConfigWithFallback()` 供 ConfigService 调用 |

---

## 域名探测策略

| 配置项 | 值 | 说明 |
|--------|-----|------|
| 单域名探测超时 | 5s | connect + receive，快速失败 |
| CDN 下载超时 | 10s | 单个 CDN 源的超时 |
| 探测方式 | 直接请求 config API | 成功即可直接使用返回数据 |
| 执行方式 | 顺序逐个 | 第一个成功即停止，避免并发 |
| 跳过策略 | 已试过的域名自动跳过 | 避免重复请求 |

---

## 持久化

| Key | 类型 | 说明 |
|-----|------|------|
| `domain_manager_working_domain` | String | 上次成功的 API 域名 |
| `domain_manager_debug_force_fail_default` | bool | 调试：强制默认域名失败 |
| `domain_manager_debug_force_fail_all` | bool | 调试：强制全部失败 |
| `domain_manager_debug_override_domain` | String? | 调试：手动指定域名 |

**策略**：缓存域名失败后自动触发 fallback 流程，不需要每次启动都重新验证。

## 备用域名部署建议

为应对 IP 封禁，备用域名的服务器部署应分散：

| 域名 | 云服务商 | 地区 | 说明 |
|------|---------|------|------|
| api.primary.com | 阿里云 | 华东 | 主域名 |
| api.backup1.com | 腾讯云 | 华南 | 不同服务商+不同地区 |
| api.backup2.com | AWS | 香港/新加坡 | 境外节点，规避境内 IP 封禁 |
| api.backup3.com | Cloudflare CDN 反代 | Anycast | 全球分布，最强抗封禁 |

核心原则：**域名不同、IP 不同、服务商不同、地区不同**，最大化单点故障容忍度。
